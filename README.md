# N2 日本語 · 學習與測驗

N2 單字與文法的離線學習網站。純靜態（HTML / CSS / 原生 JS），沒有任何建置步驟與外部依賴。

## 題庫

四個題庫並存，各自獨立記錄學習進度，在單字頁、文法頁與測驗設定都能切換。

| 題庫 | 數量 | 內容 | 可出題型 |
|---|---|---|---|
| 精選單字 | 122 | 例句、中英雙譯、手寫的表記誘答 | 全部六種 |
| 單字表 | 1350 | 假名／漢字／詞性／中文，無例句 | 漢字読み、表記、語意四選一 |
| 精選文法 | 82 | 例句、注意事項、中英雙譯、文節標記 | 全部六種 |
| 文法表 | 254 | 接續、中文意思、例句與翻譯 | 挖空四選一、填空、語意四選一 |

題庫的 id（`v` / `vl` / `g` / `gl`）同時是學習紀錄的命名空間前綴，所以
「精選單字 #1」與「單字表 #1」是兩筆完全獨立的紀錄，不會互相覆蓋。
可出的題型由資料決定：沒有例句就不會出挖空、填空、排序。

## 功能

**四種學習模式**

- **瀏覽**：清單檢視，可依詞性、關鍵字、★待加強、常錯題篩選。搜尋同時比對日文、假名、中文、英文與例句。
  預設每頁 5 筆（跟測驗的編號分組一致），用「1–5、6–10…」的分頁鈕跳頁，也可改成每頁 10／20／全部。
  「用字卡背這 N 個」「測驗這 N 個」帶的就是當下這一頁的項目，按鈕上會寫實際數量。
- **字卡**：正面可切成漢字→假名、假名→漢字、日→中、中→日四種方向；
  漢字模式不給振假名，等於盲測讀音。點卡片翻面，三段回饋（再看一次 / 下一張 / 已掌握），
  「再看一次」會把該張排到本輪最後再考一遍。
- **測驗**：四種題型可自由組合，題數 5／10／15／25／40，
  編號範圍切成 5 個一組（1–5、6–10…），可以複選任意幾組，全部用點選、不必輸入數字。
  題庫超過 200 項時會多一層百位快速跳轉，不會一次塞幾百顆按鈕。
  答錯自動加入錯題本並標記為待加強。

  | 題型 | 對應日檢 | 內容 |
  |---|---|---|
  | 漢字読み | 問題1 | 例句中的詞畫底線，選正確讀音。誘答是長音／促音／濁音／拗音／撥音的典型誤讀，不是別的字的讀音 |
  | 表記 | 問題2 | 同一個詞改成假名，選正確的漢字寫法。誘答是同音或形近的錯字，四個選項送假名一致 |
  | 挖空四選一 | 問題4 | 例句挖空選詞。誘答挑同詞性、同字尾的詞，逼你靠語意判斷 |
  | 語意四選一 | — | 日→中、中→日、讀音；文法則是文法↔意思、例句判斷 |
  | 填空 | — | 同樣挖空，但要自己打出答案，漢字與假名都接受 |
  | 排序 | — | 例句拆成文節打亂，點選重組 |

  漢字読み與表記只在「單字」範圍出現（98 個含漢字的單字），切到文法會自動改出其他題型。
- **複習排程**：每個項目記錄作答履歷，用 Leitner 間隔（1/2/4/7/14/30 天）排下次到期日。
  答對往上升一格、答錯掉回第一格；字卡的「已掌握／再看一次」也計入。
  首頁直接顯示今天有幾項到期，一鍵開成字卡或測驗。
- **統計**：正確率的 30 天趨勢圖與「最近 7 天 vs 前 7 天」進退比較、今天該複習清單、
  依單字／文法・題型・詞性拆解的正確率、頑固項目排行、六週熱力圖、掌握度進度條。
- **學習日誌**：記錄每一個有學習的日期，可切換每日／每週檢視。點開任一天就會列出
  當天第一次碰到哪些、字卡看了哪些（各幾張）、測驗考了哪些以及逐項的對錯與比分，
  答錯的會標紅並排在前面。每週檢視會把該週各天彙整起來，並列出這週練了哪幾天。
  只翻字卡沒作答的日子一樣算「有學習」，會進連續天數與熱力圖。

**考古題**（獨立分頁）

一回完整的「言語知識（文字・語彙・文法）」，54 題，分成九個大題：

| 大題 | 題型 | 題號 |
|---|---|---|
| 問題1 | 漢字読み | 1–5 |
| 問題2 | 表記 | 6–10 |
| 問題3 | 語形成 | 11–15 |
| 問題4 | 文脈規定 | 16–22 |
| 問題5 | 言い換え類義 | 23–27 |
| 問題6 | 用法 | 28–32 |
| 問題7 | 文法形式の判断 | 33–44 |
| 問題8 | 文の組み立て | 45–49 |
| 問題9 | 文章の文法 | 50–54 |

可以挑一個大題作答，也可以從頭連續作答；答完立刻看到正解與一句解析，
題號列用顏色標出答對答錯，隨時可以跳題。問題8 保留卷面的四個空格與★，
問題9 五題共用同一篇文章，目前作答的那個空格會highlight。

⚠️ **答案是推測的。**原始 PDF 沒有附解答，網站上的正解由 Claude 逐題作答，
一律標成「待確認」。對過手邊的解答之後，可以在該題按「答案沒問題」或直接改成別的號碼，
兩種都算校對過，之後判分就以你的為準。校對結果存在另一個 localStorage 鍵，
按「清除學習紀錄」不會把它洗掉。

**全站統一的顯示切換**（頂部工具列，設定會記住）

| 開關 | 作用 |
|---|---|
| 假名 | 漢字上方的振假名注音。關掉就是純日文原文 |
| 中譯 | 中文意思、注意事項、例句中譯 |
| EN | 英文意思、英文注意事項、例句英譯 |
| 例句 | 例句區塊 |
| 自動朗讀 | 進入卡片／作答後自動用日文語音唸出來 |

中譯和 EN 是各自獨立的開關，可以只看英文、只看中文，或兩個都關掉做盲測。
每一句例句都有中英雙譯與獨立的朗讀鈕。

**一個單字可以有很多句例句**，分成「考試」與「生活」兩種語感，瀏覽頁會全部列出並標明用途。
出題時會隨機挑一句，所以同一個單字連續考到也不會是同一題。目前 20 個單字各有 3 句，
其餘 102 個各 1 句；新增只要編輯 `data/sentences.csv`，振假名是自動產生的（見下方資料格式）。

**其他**

- 日文 TTS 朗讀（瀏覽器內建語音，免 API、免費）。可在設定選擇語音與語速。
- 深色模式（可跟隨系統）、字級調整。
- 鍵盤操作：字卡用 `空白鍵` 翻面、`←/→` 換卡、`S` 朗讀；測驗用 `1-4` 或 `A-D` 選答案、`Enter` 下一題。
- 學習紀錄存在瀏覽器 localStorage，可在設定中匯出／匯入 JSON 換裝置。
- 支援加到手機主畫面（PWA manifest），行動版單手可操作。

## 部署到 Vercel

1. 把 `n2-site` 這個資料夾推到 GitHub：

   ```bash
   cd n2-site
   git init
   git add .
   git commit -m "N2 日本語學習網站"
   git branch -M main
   git remote add origin https://github.com/<你的帳號>/<repo 名稱>.git
   git push -u origin main
   ```

2. 到 [vercel.com](https://vercel.com) → **Add New… → Project** → 匯入這個 repo。
3. 什麼都不用改，直接按 **Deploy**。`vercel.json` 已經指定不安裝套件、不執行建置、直接把根目錄當靜態網站發佈。
4. 之後每次 `git push` 都會自動重新部署。

### 用密碼鎖住網站

`middleware.js` 會在 Vercel 的邊緣節點擋下所有請求，沒登入就連 HTML 都拿不到，
跟前端密碼框不同（那種只是蓋住畫面，`data/*.js` 照樣能直接下載）。

登入方式是自己畫的一頁表單，通過後發一個簽名的 cookie（180 天）。
**不用瀏覽器內建的 Basic 對話框**，因為 Vercel 會把回應裡的 `WWW-Authenticate`
標頭拿掉，瀏覽器不會跳出對話框，只會把 401 的內容直接畫出來。
cookie 的內容是「到期時間 + 用密碼簽的 HMAC」，改任何一邊簽章都對不起來，
密碼本身不會離開伺服器。

帳密放在 Vercel 的環境變數，不進版控：

1. Vercel 專案 → Settings → Environment Variables
2. 新增 `SITE_PASS`（必要）與 `SITE_USER`（可省略，省略時登入頁只問密碼），
   三個環境（Production／Preview／Development）都勾
3. 回到 Deployments 重新部署一次（環境變數要重新部署才生效）

**`SITE_PASS` 沒設就完全不啟用**，所以不會發生「設一半把自己鎖在外面」的情況，
本機直接開 `index.html` 也不受影響。

部署完務必自己驗一次，middleware 沒生效的話網站會靜靜地繼續公開：

```bash
curl -I https://<你的網址>              # 應該是 HTTP/2 401
curl -I -u 帳號:密碼 https://<你的網址>   # 應該是 HTTP/2 200（Basic 仍相容，方便檢查）
```

改密碼就改環境變數再重新部署——舊的 cookie 是用舊密碼簽的，會立刻全部失效。
要暫時關掉保護就把 `SITE_PASS` 刪掉。

**必要檔案**：`index.html`、`css/`、`js/`、`data/` 這四項缺一不可。
`manifest.webmanifest` + `icon.svg` 只影響「加到手機主畫面」，`vercel.json`、`package.json`、
`README.md`、`tools/` 都不影響網站運作，刪掉也能跑。`middleware.js` 只在
Vercel 上生效，本機開檔案不會被它擋。

本機預覽直接用瀏覽器打開 `index.html` 就可以，不需要起伺服器。

## 資料格式

資料在 `data/vocab.js` 與 `data/grammar.js`，是兩個 JS 全域陣列（用 JS 而不是 JSON，這樣 `file://` 直接開也能載入）。

**單字**

```js
{
  "id": 1, "group": 0, "pos": "名詞",
  "word": "影響",
  "wordRuby": "影響{えいきょう}",     // 注音標記
  "reading": "えいきょう",
  "en": "influence", "zh": "影響",
  "ex": "彼{かれ}の/発言{はつげん}は/…",  // 標注過的例句
  "clozeIdx": 4,                      // 填空題挖掉第幾個詞塊（0 起算）
  "clozeAnswer": "影響",              // 空格裡該填的字
  "clozeKana": "えいきょう",           // 同上的假名寫法（作答時兩種都接受）
  "clozeTail": "を",                  // 留在空格外面的助詞／標點
  "qWord": "影響",                    // 漢字読み／表記題在例句中要畫底線的那一段
  "qKana": "えいきょう",               // 它的讀音
  "qStem": "影響",                    // 語幹（不含送假名）
  "wrongKanji": ["映響","影郷","影鏡"], // 表記題的誘答
  "exZh": "他的發言對輿論造成了很大的影響。",
  "exEn": "His remarks had a big influence on public opinion."
}
```

**文法**

```js
{
  "id": 1, "pattern": "～あげく（に）",
  "meaning": "…到最後、結果卻…。…",
  "meaningEn": "After a long process, in the end… (usually badly)",
  "note": "後項幾乎都是負面…",
  "noteEn": "The outcome is almost always negative…",
  "usage": ["動詞た形＋あげく（に）", "名詞＋の＋あげく（に）"],
  "ex": "長時間{ちょうじかん}/話{はな}し合{あ}ったあげく、/…",
  "exZh": "討論了很久，結果還是沒得出結論。",
  "exEn": "After talking it over for a long time, we still reached no conclusion.",
  "cloze": "あげく",                   // 填空題要挖掉的字串
  "variants": ["あげくに", "あげく"]    // 填空可接受的其他寫法
}
```

### 學習紀錄結構（localStorage）

```js
{
  marks: { "v:12": "weak" | "known" },              // 手動標記
  log:   { "2026-09-03": {
    n, ok,                              // 當天測驗題數與答對數
    byType: { reading:{n,ok}, … },      // 依題型
    items:  { "v:12": {n,ok} },         // 當天每個項目考了幾次、對幾次
    cards:  { "v:12": {n,ok} },         // 當天字卡看了幾張、按了幾次「已掌握」
    fresh:  ["v:12"]                    // 當天第一次碰到的項目
  } },
  items: { "v:12": { a, m, s, last, due, box } },   // 每個項目的完整履歷
  //       a=累計作答 m=累計答錯 s=連續答對 last=上次日期 due=下次到期 box=Leitner 盒號
  types: { reading:{n,ok}, writing:{n,ok}, cloze:{n,ok}, mc:{n,ok},
           fill:{n,ok}, sort:{n,ok}, card:{n,ok}, past:{n,ok} },
  wrong: { "g:5": 3 }, seen: { "v:1": 2 }, v: 2      // 舊版欄位，保留供相容
}
```

考古題另外存在 `n2.past.v1`，跟學習紀錄分開：

```js
{
  keys:  { "past1:12": { n: 3, at: "2026-09-03" } },   // 你校對過的正解
  picks: { "past1:12": 2 }                             // 你選的答案
}
```

分開存的理由是「清除學習紀錄」不該把校對結果一起洗掉——那是花時間對出來的，
而作答紀錄隨時可以重做。考古題的作答本身仍然會進 `log`、`wrong`、`types.past`，
所以學習日誌與統計都看得到；但它不進 Leitner 複習佇列（一回考卷是一次性的，
不適合當間隔重複的素材），錯題要複習就用考古題頁的「只看答錯的」。

舊版（只有 marks/log/wrong/seen）的紀錄會在開啟時自動補出 `items`，原有欄位一個都不刪。
遷移是依「內容」而非版本號判斷，所以重複開啟不會重跑，也不會漏掉。
注意：過去的作答補不回時間與題型，趨勢圖與題型分析從升級後才開始累積。

### 例句：一個項目可以有很多句

每個單字／文法的例句放在 `exs` 陣列裡，每一句自己帶翻譯與挖空位置：

```js
exs: [
  { ex: "彼{かれ}の/発言{はつげん}は/…", exZh: "…", exEn: "…", use: "core",
    clozeIdx: 4, clozeAnswer: "影響", clozeKana: "えいきょう", clozeTail: "を" },
  { …, use: "exam" },   // 考試會用的句子
  { …, use: "life" }    // 生活旅遊會用的句子
]
```

挖空位置必須每句各算一次——同一個單字在不同句子裡的文節位置與後面的助詞都不同。

`exs[0]` 是原本那一句，頂層的 `ex` / `exZh` / `exEn` / `cloze*` 仍然指向它，
所以既有程式一行都不用改。出題時 `Quiz.withSentence()` 會隨機挑一句覆寫這些欄位，
同一個單字連續考到也不會是同一題。**漢字読み與表記例外**，這兩種題型的底線位置
是照第一句算出來的，換句子會對不上，所以固定用 `exs[0]`。

新增例句只要編輯 `data/sentences.csv`：

```csv
deck,id,use,ja,zh,en
v,1,exam,円安の影響で、輸入品の値段が上がっている。,受日圓貶值的影響…,Because of the weak yen…
```

只填手打的部分。**振假名與文節不要寫進 csv**，由 `tools/furigana.py` 產生，
挖空位置由 `gen_data.py` 算，這樣不會有兩份互相矛盾的資料。改完跑：

```bash
cd tools && python3 gen_data.py
```

### 例句標注規則

例句用一個字串同時表達三件事：

- `漢字{かな}` — 振假名。底字只能是漢字，假名寫在外面。
  正確：`話{はな}し合{あ}った`　錯誤：`話し合{はなしあ}った`
- `/` — 文節分隔，同時決定**排序題的詞塊**。詞塊少於 3 個的句子不會出排序題。
- 其餘照原文寫，包含標點。

去掉 `{}` 和 `/` 之後必須等於原始例句 — `tools/gen_data.py` 會自動檢查，不符就報錯。

## 之後要加資料（例如文法下篇）

`tools/` 裡有產生資料檔的腳本：

- `pdf_vocab.py` — 從 `resources/9.pdf` 抽 1350 個單字（靠字級與 x 座標切欄位）
- `pdf_grammar.py` — 從 `resources/1.pdf` 抽 254 條文法，並用座標把振假名還原成 `漢字{かな}`
- `parse.py` — 讀 `Quiz/*.txt` 和 `N2文法144_上篇.xlsx`，輸出中繼 JSON
- `anno.py` — 例句的假名／斷詞標注表（手寫，逐句對照）
- `trans.py` — 例句中英翻譯、文法的英文意思與注意事項（手寫）
- `kanji.py` — 表記題的誘答漢字，每個含漢字的單字各 3 個同音／形近錯字（手寫）
- `furigana.py` — 自動上振假名與文節（MeCab）。含例外對照表；直接執行會拿現有
  204 句手寫標注當回歸測試，目前原文還原與整句讀音都是 100%
- `gen_data.py` — 合併、驗證標注、計算填空位置，輸出 `data/*.js`
- `pdf_past.py` — 抽考古題。靠字級與座標分辨內文（11.3pt）、振假名（5.6pt）、
  題號（9.2pt）與側邊直排標籤；卷面的底線用「線上面有沒有字」分成兩種——
  有字是問題1・2・5 要考的詞，沒字是問題8 的空格
- `past_answers.py` — 考古題的答案與解析（手寫，未經官方校對）
- `gen_past.py` — 合併題目與答案、驗證，輸出 `data/past.js`

```bash
pip install openpyxl pdfplumber fugashi unidic-lite

# 精選題庫（122 單字 / 82 文法）
cd tools && python3 parse.py && python3 gen_data.py

# 從 PDF 抽出的題庫（需要 resources/ 裡的原始檔）
python3 pdf_vocab.py && python3 pdf_grammar.py

# 考古題（7.pdf 前半的文字語彙 ＋ 3.pdf 後半的文法）
python3 pdf_past.py && python3 gen_past.py
```

**原始 PDF 不在版控裡**（`resources/` 已加入 `.gitignore`），因為那是官方考古題
與他人製作的整理表。抽取後的 `data/*.js` 有進版控，所以網站可以直接部署；
要重新產生資料才需要把 PDF 放回 `resources/`。

`gen_data.py` 有五道自動檢查，任何一道沒過就直接中止、不會產出壞資料：

1. 每句標注去掉 `{}` 和 `/` 後，必須等於原始例句
2. 單字填空的「答案 + 尾巴」必須能還原成原句
3. 文法的挖空字串若是被截短來的（可能挖到詞的一半），會列出來要求你在 `CLOZE_OVERRIDE` 手動指定
4. 每一筆都必須有對應的中英翻譯，缺一筆就中止
5. 含漢字的單字必須有 3 個誘答漢字，且字數與語幹相同、彼此不重複

### 測試

`tools/` 裡另外有十四支測試，改完程式或資料後跑一次：

```bash
npm i jsdom
npm test               # 一次跑完下面十四支

node tools/auth.js     # 登入保護：未設定不啟用、登入表單、cookie 簽章與偽造、轉址跳板
node tools/audit.js    # 全站互動稽核：CSS 可見性、五個分頁、篩選、字卡、測驗、統計、設定
node tools/decks.js    # 題庫：資料完整性、紀錄命名空間隔離、依資料決定題型、介面切換
node tools/paging.js   # 分頁、每頁筆數、中英雙譯開關、例句朗讀內容
node tools/batch.js    # 「這批」＝當頁：字卡與測驗帶到的項目必須跟畫面上的完全一致
node tools/range.js    # 題數與編號分組：複選與取消、出題確實落在選取組內、切換單字↔文法時重設
node tools/review.js   # 複習排程：舊紀錄遷移、Leitner 間隔、到期佇列、題型統計、趨勢計算
node tools/journal.js  # 學習日誌：逐項明細、使用日期、每週彙整、展開收合、舊紀錄相容
node tools/cloze.js    # 挖空四選一品質：選項不重複、誘答不模稜兩可、題幹不洩漏答案
node tools/kanji.js    # 漢字読み／表記：誘答是合法假名、送假名一致、題幹不洩漏答案、字卡四方向
node tools/sentences.js # 多例句：資料完整性、測驗會換句子、瀏覽列出全部、判分不受影響
node tools/past.js     # 考古題：54 題資料完整性、作答流程、校對正解、與首頁統計日誌的串接
node tools/judge.js    # 判分正確性：204 題填空、165 題排序
node tools/t.js        # 出題引擎壓力測試：1200 題
```

也可以直接手動編輯 `data/*.js` 加條目，只要照上面的格式即可。
